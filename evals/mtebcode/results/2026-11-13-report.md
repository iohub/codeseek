## 5. Reproduction Commands

**Precondition -- the adaptive cutoff must be disabled.** The retrieval results below were produced with `index.hybrid.cutoff.enabled = false`. With the default (`true`) the three-gate adaptive cutoff trims a short query down to roughly **one** result, which collapses `nDCG@10`, `recall@10` and `MRR@10` onto the same number and turns most queries into `unknown_empty` -- the score then measures the cutoff, not retrieval.

1. Merge the snippet below into `~/.codeseek/config.json` -- **merge, never overwrite**, so that the `embedding` section holding `api_token` survives:

```json
{"index": {"hybrid": {"cutoff": {"enabled": false}}}}
```

2. Run the commands below, then **restore the previous configuration**. `~/.codeseek/config.json` is the only place the cutoff can be changed: there is no CLI flag and no environment variable for it.

For this batch, with the cutoff disabled, the result lists stay full: `mean_returned = 20.00` and `unknown_empty = 0` over 100 queries -- the same numbers as Sections 1-3 above.

```bash
# Run from the repository root; every artifact lands under --workdir
cd evals/mtebcode

# 0) Offline self-test: nDCG arithmetic / tolerant parsing / doc_id mapping / rendering
#    (no network, no codeseek binary)
python3 -m mtebcode_eval selftest

# 1) Fetch the dataset + sample queries + pool the corpus + materialize (real parameters of this batch)
python3 -m mtebcode_eval prepare \
  --workdir /tmp/mtebcode-ts \
  --tasks CodeEditSearchRetrieval-go,CodeEditSearchRetrieval-python,CodeEditSearchRetrieval-typescript,CosQA \
  --limit-queries 20 \
  --corpus-size 300 \
  --seed 42 \
  --parquet-cache ~/.cache/huggingface/hub \
  --proxy http://127.0.0.1:7897
#   --proxy points at a local proxy; replace it with your own. A direct connection to
#   datasets-server is usually rate-limited (HTTP 429).
#   --parquet-cache reads a (config, split) straight from the local HF cache without a
#   network request; drop it (or use --cache-only) for a fully offline reproduction.

# 2) Run retrieval and write the report (--force ignores existing raw results; search_limit / k below)
python3 -m mtebcode_eval run \
  --workdir /tmp/mtebcode-ts \
  --limit 20 \
  --k 10 \
  --concurrency 4

# 3) Re-score only (no retrieval re-run; change k here for a k-sensitivity check)
python3 -m mtebcode_eval score \
  --workdir /tmp/mtebcode-ts \
  --limit 20 \
  --k 10
```
